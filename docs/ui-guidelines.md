# 桌面端 UI 交互与文案规范

面向**改 `app/` 的人**。这里不是灵感清单，而是这个产品已经在用的规则：
新增界面、改状态流、写提示语之前先读一遍，评审时按这里的条目对照。

相关文档：[桌面外壳说明](../app/README.md) · [维护手册](maintenance.md) ·
[桌面端变更记录](../CHANGELOG.md)

---

## 0. 产品前提

- 用户是**正在写代码的开发者**，不是来逛应用的。打开应用只有一个目的：
  **截图 → 拿到文字 → 回编辑器粘贴**。
- 本地工具不该制造停留时间。一次成功操作最好的反馈就是结果本身，
  不需要“操作成功”的庆祝。
- 截图随时可能被打断（快捷键、权限、模型没下、服务没起）。
  因此**恢复路径和主路径同等重要**。
- 用户对技术细节不陌生，但**不需要在第一时间看到它们**。
  技术信息放第二层，且只在能帮助排障时出现。

三条硬指标，任何改动都不能破坏：

1. 从按下快捷键到结果进剪贴板，中间不出现无法继续的状态。
2. 任何阻塞状态都同时给出**原因**和**一个主要下一步**。
3. 同一时刻，标题栏、侧栏、截图页对“现在能不能截图”的说法必须一致。

## 1. 交互设计原则

### 1.1 只有一个状态机

“能不能截图”由 `app/src/lib/status.ts` 的 `captureReadiness()` 统一判定，
标题栏、侧栏、截图页、设置页都读同一份结果。**禁止在组件里另写一套状态文案**。

状态优先级从高到低：

| 优先级 | 状态 | 标题栏 | 色调 | 页面表现 | 主要动作 |
|---|---|---|---|---|---|
| 1 | 正在选区 / 识别 / 启动 | 选择区域中 / 正在识别 / 正在启动 | ok | 显示阶段条 | 无（等待） |
| 2 | 快捷键注册失败 | 快捷键不可用 | warn | Toast + 设置入口 | 修改快捷键 |
| 3 | 状态未知 | 检查中 | muted | 正常界面 | 无 |
| 4 | 需要模型 | 需要下载模型 | warn | 配置横幅 + 弹窗 | 下载模型 |
| 5 | 需要屏幕权限 | 需要授权 | warn | 授权横幅 + 弹窗 | 去授权 |
| 6 | tesseract 不可用 | tesseract 不可用 | danger | 错误面板 | 检查设置 |
| 7 | 引擎启动中 / 失败 | 正在启动 / OCR 引擎出错 | ok / danger | 阶段条 / 错误面板 | 等待 / 重试 |
| 8 | 运行时缺失 | 运行时缺失 | danger | 错误面板 | 重装完整版本 |
| 9 | 可以截图 | 就绪 / 待启动 | ok / muted | 主按钮可用 | 截图 |

约定：

- **模型先于权限**。两者都缺时，先完成模型下载，再授权屏幕录制；
  设置向导的最后一步会引导授权。不要在用户还没装模型时先弹权限框。
- `待启动` 不是错误：模型已装、引擎按需启动，截图仍然可用，所以是 muted 而不是 warn。
- 文案跟随状态，不要跟随实现。托管引擎统一叫“OCR 引擎”，不叫 `llama-server`；
  备用方案直接写 `tesseract`。

### 1.2 每个阻塞态都必须有出口

- 阻塞状态出现时，**页头主按钮改为对应动作**（下载模型 / 去授权），
  而不是把按钮藏起来。
- 页面上同时保留横幅，说明“为什么现在不能截图”。
- **已有旧结果时也要显示阻塞横幅和主按钮**，不能让用户看着上一次的结果
  却找不到恢复入口。
- 错误面板统一给两个动作：一个主要恢复动作（重试截图 / 下载模型 / 去授权），
  一个次要动作（打开设置）。不要只显示错误文本。

### 1.3 首次引导：可跳过、可续传、可重来

| 阶段 | 用户看到 | 必须支持 |
|---|---|---|
| 未安装模型 | 模型大小、下载一次、本地处理 | 下载、稍后设置、关闭弹窗 |
| 下载中 | 当前文件、百分比、速度、ETA | 后台继续、取消下载、校验/加载阶段不显示取消 |
| 失败 | 原始错误、复制错误、镜像/代理入口 | 重试、下载设置、稍后再说 |
| 就绪 | 模型与平台信息、下一步 | 截第一张图 / 授权屏幕录制 |
| 权限未开 | 三步说明、系统设置入口 | 授权、打开系统设置、重新检查、重启应用、稍后再说 |

- 首次引导**只自动弹一次**。用户跳过就记住，之后用横幅提醒，不再反复打断。
- 下载转后台后 Rust 线程继续跑，侧栏保留进度；重新打开弹窗必须显示真实进度，
  **不能重置为 0**。
- 取消只出现在“取消真的能停下来”的阶段。Rust 不支持中断校验/加载时，
  不显示取消按钮，避免“点了没反应”。
- “重新显示引导”必须清掉旧结果和旧错误，否则步骤面板没有位置出现；
  如果仍然缺模型或缺权限，直接打开对应弹窗。

### 1.4 不丢用户已经拿到的结果

- 新的阻塞提示、错误、弹窗都**不清空**当前识别结果；结果只在下一次截图成功时替换。
- 识别结果可能被截断时（结果行数明显少于截图行数），照样保留结果，
  在结果面板底部加一行提示 `识别结果可能不完整。` 和 `重新识别（分块）` 按钮；
  不弹 Toast，不打断操作。重试复用同一张截图，成功后才替换结果。
- 清空历史、移除模型这类不可撤销操作：
  1. 第一次点击进入确认态，按钮文字变成明确的危险动作（如“再点一次清空”）；
  2. 确认态自动复位（历史 4 秒、移除模型 5 秒），不长期挂着；
  3. 确认按钮用危险色，取消保持普通样式。
- 不要用 `window.confirm` / `alert`。项目内统一用面板内确认或专用弹窗。

### 1.5 区分“立即生效”和“保存后生效”

| 类型 | 例子 | 交互 |
|---|---|---|
| 立即生效 | 下载/启动/停止/移除模型、检查更新、安装更新、请求权限 | 点击即执行，按钮显示进行中 |
| 保存后生效 | 快捷键、精度、输出格式、代理、提示词、并行数、界面缩放 | 先改草稿，底部保存栏提示未保存 |

- 设置页必须明确显示 `已保存 / 有未保存的更改 / 有字段需要修正后才能保存`。
- `⌘S` / `Ctrl+S` 保存；在快捷键录制器里不拦截，交给录制器。
- 保存按钮因校验而禁用时，**保存栏要说明原因**，不能只是灰掉。
- 校验只在相关字段可见时生效。比如 tesseract 模式不因为 URL 为空而阻止保存；
  纯文本模式不校验围栏语言。
- 同一份设置不要在两处维护文案。默认值、单位、范围以 `lib/defaults.ts` 和 Rust
  `settings.rs` 为准。

### 1.6 渐进披露，默认值先能用

设置分五段，按用户意图组织，不按代码模块组织：

| 分区 | 放什么 | 判断标准 |
|---|---|---|
| 通用 | 快捷键、自动复制、界面缩放、屏幕权限 | 每次装机都要看一眼 |
| OCR | 引擎健康、模型下载/启动/移除、精度、空闲释放、下载设置 | 决定“认不认得出来” |
| 输出 | 格式、围栏语言、历史条数、版面处理 | 决定“拿到什么形状” |
| 高级 | 引擎模式、外部服务地址、提示词、max tokens、并行数、KV、tesseract | 改错会坏，或很少改 |
| 关于 | 版本、隐私、更新、重新引导、退出 | 排障与生命周期 |

- 新选项先问：**第一次使用的人需要看到它吗？** 不需要就进“高级”或折叠区。
- 下载镜像、代理放在 `<details>` 折叠里；技术细节（运行时、SHA-256、模型来源）
  放在“技术详情” `<details>` 里。
- 默认值必须能完成主流程。高级选项是给排障和极端场景的，不是必经之路。

### 1.7 反馈分层

| 场景 | 反馈方式 | 时长/位置 |
|---|---|---|
| 截图成功 | 结果面板 + 剪贴板 + 首图提示 | 直到下一次截图 |
| 截图成功且窗口不在前台 | 系统通知：首行摘要 + 行数 + 是否已复制 | 直到用户处理 |
| 截图失败 | 页面错误面板（含原因与下一步） | 直到下一次操作 |
| 后台动作完成 | Toast | 3.6 秒 |
| 错误 Toast | Toast，`role=alert` | 6 秒 |
| 进行中 | 阶段条 / 进度条 / 按钮文字变化 | 持续到结束 |
| 快捷键不可用 | Toast + 设置页状态 | 6 秒 + 持久状态 |

- 系统通知只在主窗口**没有焦点**时发；窗口在前台时结果面板已经足够，
  不再叠加应用内成功 Toast。通知内容可能包含代码，设置里可以关闭
  （通用 → 识别完成通知）。

- **常规成功不弹成功 Toast**。识别成功、复制成功都以界面结果为准。
  （从历史复制、清空历史这类没有页面结果的动作才用 Toast。）
- 进度必须包含**阶段名**（下载 / 校验 / 加载）和真实数据（百分比、速度、ETA）。
  校验和加载阶段不要伪造百分比。
- 任何异步按钮在执行期间 disabled 并改文案（`保存中…`、`正在启动…`），
  防止重复点击；重复启动不能把可见进度重置为 0。

### 1.8 键盘与焦点

- 全局快捷键：只有 **F1–F24 可以单独使用**；字母、数字、空格、方向键必须带修饰键，
  否则会吞掉其他应用的输入。
- 录制快捷键期间暂停全局快捷键，离开设置页必须恢复（`ShortcutRecorder` 的清理逻辑）。
- `Esc` 关闭弹窗、取消选区；选区同时支持右键取消。
- 弹窗：
  - 打开时聚焦主按钮；主按钮禁用时聚焦弹窗本身；
  - `Tab` 焦点锁在弹窗内；
  - 内容分支切换（下载中、权限已授予）后**重新聚焦**；
  - 关闭时把焦点还给触发元素。
- 图标按钮必须有 `aria-label` 和 `title`；纯装饰图形 `aria-hidden`。
- 错误用 `role="alert"`；普通进度/提示用 `role="status"` + `aria-live`。

### 1.9 平台差异

- macOS：截图前用 `CGPreflightScreenCaptureAccess` 检查权限，没有就引导授权；
  系统设置深链 `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`。
- Windows：自绘选区 + GDI，不需要屏幕录制权限，不要显示权限相关文案。
- 快捷键显示：macOS 用 `⌘ ⇧ ⌥`，Windows 用 `Ctrl Shift Alt`；
  统一走 `shortcutText()`，不要在组件里拼字符串。
- 平台专属文案用 `isMac` 分支，不要写“如果系统要求…”。

### 1.10 预览与验收

浏览器预览走 mock 总线，不依赖模型和权限：

```bash
cd app
pnpm dev
# http://127.0.0.1:1420/?demo=result|setup|permission|error|history|settings
```

- 至少检查 1280×900 和 900×700 两个尺寸，以及完整页面滚动后的底部。
- 弹窗要检查分支切换后的焦点：只用键盘完成“下载 → 校验 → 就绪”和
  “未授权 → 已授权”两个转换。
- 真实平台相关的行为（macOS 权限、Windows 自绘选区）必须在真机验证，
  mock 预览不能替代。

### 1.11 预览不是结果

识别过程中会出现两种预览，它们都只用于缩短等待，**不是可复制的结果**：

| 场景 | 首层文案 | 说明 |
|---|---|---|
| 模型流式输出 | 正在识别 | `ocr:partial` 的累积文本；完成后由 `ocr:result` 替换 |
| macOS 快速预览 | 快速预览 | 系统 OCR 先出的文本，随后由本地模型精修 |

- 预览**不写入历史、不自动复制、不触发完成通知**；只有 `ocr:result` 这样做。
- 不要在预览上再发明一套状态词；状态机仍然是“正在识别”。
- 预览失败要静默回退到正常识别，不要用一个错误面板打断主流程。

## 2. 文案原则

### 2.1 语气：像同事提醒，不像客服话术

直接、平静、具体、克制。

- 说**用户要做什么**，不说系统内部发生了什么。
- 一句话只表达一件事；标题给结论，正文给原因或下一步。
- 不用“您”。标题、按钮、Toast 不用“请”；正文里需要明确指向用户操作时
  最多保留一个“请”，能直接写动作就写动作（“检查设置后重试”优于“请您检查设置后重试”）。
- 不用“请稍候”“感谢耐心等待”“正在努力”这类填充语；少用“即可”，
  只在能明确表达“这一步做完就够了”时保留。
- 不用感叹号，不用“强大的”“智能的”“一站式”“无缝”这类形容词。
- 不承诺结果，不制造焦虑。权限没开就说截图会空白，不写“为了保护您的隐私”。

### 2.2 标题与正文

| 位置 | 规则 | 示例 |
|---|---|---|
| 弹窗标题 | 状态或动作，≤ 12 字 | `启用本地 OCR 引擎`、`设置没有完成`、`权限已开启` |
| 页面标题 | 一个名词 | `截图`、`历史`、`设置` |
| 正文 | 原因 + 下一步，1–2 句 | `下载一次 OCR 模型，之后截图都在本机处理。` |
| 按钮 | 动词 + 对象，2–6 字 | `下载模型`、`去授权`、`重试截图`、`保存更改` |
| 错误标题 | 发生了什么，不写“错误” | `截图区域是空白的`、`识别没有完成` |
| Toast 标题 | 结果或下一步，≤ 12 字 | `OCR 模型已就绪`、`无法启动 OCR 引擎` |

### 2.3 术语表

界面统一用左列；中列只允许出现在“高级”、技术详情或原始错误里。

| 界面用词 | 不要用 | 说明 |
|---|---|---|
| OCR 模型 | 识别模型、权重、GGUF | 用户下载的那个东西 |
| OCR 引擎 | 识别服务、llama-server、引擎、后端 | 在后台跑模型的进程 |
| 引擎模式 | 识别引擎 | 高级里的 auto / llama.cpp / tesseract 选择 |
| tesseract | 备用识别、备用引擎、兜底引擎 | 系统装了才可用的第二方案 |
| 运行时 | llama.cpp 二进制、DLL | 只用于“运行时缺失”排障和技术详情 |
| 屏幕录制权限 | 截屏权限、录屏权限 | 系统设置里的原名 |
| 本地处理，不上传 | 隐私保护、数据安全 | 本地模式的一句话数据去向；远程模式改说“截图发到你的服务器” |
| 部署到服务器 | 远程引擎、云端识别 | 把模型放到自己的 Linux 服务器 |
| 服务器识别 | 远程推理、SSH 隧道 | 用户视角的结果，不暴露端口/隧道细节 |
| 截图 | 截屏、抓屏、捕获 | 全项目统一 |
| 快速预览 | 系统 OCR、Vision、预识别 | 先用系统 OCR 出文本、再由模型精修的中间结果；不是最终结果 |
| 历史 | 记录列表、剪贴板历史 | 页面名与空状态一致 |
| 下载 / 校验 / 加载 | 安装中、处理中 | 三个阶段分开说 |
| 外部服务 | 远程引擎、自定义后端 | 非托管 llama.cpp |

远程连接只用「连接中 / 已连接 / 重连中 / 失败」四个词，第一层不出现端口、
URL、`ssh` 命令或 `ssh -L`：

| 状态 | 首层文案 | 必须提供的动作 |
|---|---|---|
| 建立连接 | 连接中 | 等待 |
| 正常 | 已连接 | 停止远程服务 |
| 隧道断开、自动重试 | 重连中（第 n 次，共 5 次） | 停止重连；重试耗尽后「重连」 |
| 重试耗尽 | 失败 | 「重连」或「停止远程服务」 |

重连耗尽后按 2.5 的错误公式写，例如：`和服务器断开了，自动重连 5 次没有成功。`
+ `确认服务器在线、网络正常，然后点「重连」。` 侧栏、标题栏和截图页读
`captureReadiness()` 的同一份结果，不得在组件里另写一套连接状态。

### 2.4 按钮与确认

- 优先写清动作，不写“确定 / 取消”。弹窗的两个按钮应能单独看懂。
- 危险操作的确认按钮要重复危险本身：
  `清空记录` → 确认态 `再点一次清空`；`移除模型` → 确认面板里的 `移除`。
- 关闭弹窗的按钮根据阶段变化：`稍后设置` / `后台继续` / `稍后再说` / `完成`，
  不要一律叫“取消”。
- 链接按钮用于次要动作（`打开系统设置`、`重启应用`、`复制错误`），
  主按钮用于推进流程。

### 2.5 错误文案公式

```text
[发生了什么，短句]
[下一步，一个具体动作]
```

- 主文案不出现 `E_*`、堆栈、状态码、URL、文件路径。
- 设置向导的“复制错误”和技术详情保留原始信息，方便反馈排查。
- 不责怪用户，不写“您输入有误”。写清哪个字段、怎么改。
- 能给出具体位置就给出：`系统设置 → 隐私与安全性 → 屏幕录制`。

错误类型与默认表达（`OcrError.code`）：

| code | 标题 | 正文重点 | 主要动作 |
|---|---|---|---|
| `permission` | 需要屏幕录制权限 | 没权限截出来会是空白 | 去授权 |
| `setup-required` | 先下载 OCR 模型 | 下载一次，之后都在本机处理 | 下载模型 |
| `blank` | 截图区域是空白的 | 重新框选包含文字的区域 | 重试截图 |
| `engine` | 识别没有完成 | OCR 引擎没响应/还在加载 | 重试截图 + 检查设置 |
| `capture` | 这次截图没有成功 | 选区或系统截图失败 | 重试截图 |

### 2.6 标点、数字与中英混排

- 中文正文用全角标点；中英文之间加空格：`下载 GLM-OCR 模型`。
- 省略号用 `…`，不用 `...`。
- 快捷键统一 `⌘S`、`⌘⇧2`、`Ctrl+S`，不要写 `Cmd+S` 或 `ctrl + s`。
- 数字给单位和范围：`1.4 GB`、`10–20 秒`、`最近 20 条`；不要写“较大”“很快”。
- 英文专名保留原大小写：`tesseract`、`llama.cpp`、`SHA-256`、`Hugging Face`。
- 不用 emoji 当图标；图标统一走 `components/Icon.tsx`。

### 2.7 “AI 味”对照

| 不要写 | 改成 |
|---|---|
| 正在进行模型下载，请稍候… | 正在下载模型 |
| 本地 OCR 引擎尚未安装 | OCR 模型还没有下载 |
| 请打开设置检查引擎和版面选项，然后重试。 | 检查设置后重试。 |
| 抱歉，截图失败了，请稍后再试。 | 这次截图没有成功 |
| 您的数据将被安全地保存在本地。 | 截图和文字不会离开这台电脑。 |
| 一键启用强大的本地 OCR 能力 | 下载一次 OCR 模型，之后截图都在本机处理。 |

## 5. 评审时怎么判

按严重程度从高到低：

1. **无路可走**：阻塞态没有入口、错误后不能重试、弹窗只能强退。
2. **状态矛盾**：标题栏说就绪，页面说没服务；侧栏和设置页说两套话。
3. **丢数据/误操作**：清空无确认、切换视图丢草稿、重试重置下载。
4. **键盘不可用**：焦点逃出弹窗、快捷键吞输入、图标无标签。
5. **文案问题**：技术名词泄漏到首层、错误没有下一步、AI 味表达。

前三条不合并；后两条可以在同一轮修完。
